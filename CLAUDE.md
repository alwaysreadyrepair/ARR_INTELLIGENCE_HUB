# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ARR Intelligence Hub: ARR Heating + Cooling's central internal tool hub. Property, market, weather, ingestion and SEO/AEO dashboards. Status is a v1 shell on mock data, not deployed anywhere, and it must not be deployed anywhere reachable until Supabase Auth is in. `README.md` is the reference (routes table, SEO refresh steps, the "Connecting Supabase" plan, known placeholders); `docs/INTELLIGENCE-HUB-DATA-PLATFORM.md` and `docs/adr/` hold the Phase 2 property-data plan.

It was split out of the pricing app's monorepo (`alwaysreadyrepairhvac/arr_instant_pricing`, `apps/intelligence-hub`) and shares no code with it. The county connectors, address normalizer and Supabase loaders the Phase 2 doc mentions still live in that repo.

## Commands

Node ≥ 22.23.4 (Astro 7 refuses to start below it; `.nvmrc` says 22). CI (`.github/workflows/ci.yml`) runs `npm test`, `npm run check` and `npm run build` on every push; run all three before calling work done.

```
npm install
npm run dev        # http://localhost:4322 (port pinned); Astro 7 detaches it: `npx astro dev stop|status|logs`
npm test           # node --test over src/**/*.test.ts (lib, SEO, mock repositories)
npm run check      # astro check (types)
npm run build      # Astro build, Cloudflare adapter (a Worker; Pages support is gone)
npm run preview    # astro preview of the build in workerd, same port
npm run types      # wrangler types -> worker-configuration.d.ts (git-ignored); dev/check/build run it first

# One test file, optionally filtered by test name:
node --experimental-strip-types --no-warnings=ExperimentalWarning --test --test-name-pattern="freshness" src/lib/lib.test.ts

npm run seo:refresh -- --dry-run        # SEO & AEO refresh plan and paid-call cost; drop --dry-run to run it (spends money)
npm run seo:refresh -- --only=audit     # free site crawl only, no credentials needed
npm run seo:refresh -- --sandbox        # DataForSEO's free sandbox: checks credentials and request shapes
npm run seo:load                        # load .seo/snapshot.json into the local SEO KV
```

Tests run TypeScript directly through Node's type stripping, so relative imports use explicit `.ts` extensions and code under test can't use TS-only runtime syntax (enums, namespaces, parameter properties).

Env: `DATA_SOURCE` and `SEO_DATA_SOURCE` are `wrangler.json` vars (override locally in `.dev.vars`). Server code reads bindings and vars via `import { env } from 'cloudflare:workers'` (only `src/middleware.ts` does today); `Astro.locals.runtime` was removed in Astro 6 and throws. The `Env` type is generated by `wrangler types`; extra settings are merged into it in `src/env.d.ts`. Sessions and the image service are off in `astro.config.mjs` so no SESSION KV or IMAGES binding gets provisioned. DataForSEO credentials for `seo:refresh` go in `.env` (`DATAFORSEO_LOGIN` + `DATAFORSEO_PASSWORD`, or `DATAFORSEO_API_KEY`).

## Architecture

- Astro SSR on the Cloudflare adapter. Global filters (territory, date range, data source) live in the query string, so pages work without JS; `href()` in `src/lib/filters.ts` carries them between pages.
- **Data flow:** `src/middleware.ts` attaches the stub user, `Astro.locals.repos` (from `getRepositories(env)` in `src/repositories/index.ts`), the request clock and `?simulate` to every request. Pages call repository methods (interfaces in `src/repositories/types.ts`) wrapped in `load()` (`src/lib/load.ts`), which returns `ok | stale | empty | error`; `Panel.astro` renders each state so a failing panel never takes down the page. Stale thresholds live only in `STALE_AFTER_DAYS` (`src/lib/freshness.ts`). The weather-vs-demand panel is a server island (`server:defer`) with a `Skeleton` fallback.
- v1 runs on mock data (`src/data/mock/`), which **only** `src/repositories/mock/` may import. `?simulate=error|empty|slow` forces states in mock mode only. Some mock staleness is deliberate (Lyons and Worth townships are months old; Will County was never ingested).
- `DATA_SOURCE=supabase` (or any unknown value) deliberately makes every panel error via a rejecting proxy, never silently falling back to mock. The Supabase work is planned step by step in README "Connecting Supabase": aggregations become SQL views/RPCs, one class per repository interface in `src/repositories/supabase/`, anon key + RLS (no `service_role` in the Worker), and the mock repository tests reused as a contract test.
- Data families stay in separate models and are never copied onto each other: property facts, weather (stored once per `WeatherArea`; a property only carries `weatherAreaId`), Sera demand, and SEO.
- **SEO & AEO tab (`/seo/*`)** has its own source switch, `SEO_DATA_SOURCE=mock|snapshot`, independent of `DATA_SOURCE`. Both build one `SeoSnapshot` (`src/domain/seo.ts`); snapshot mode reads it from the `SEO` KV key `seo:snapshot`, written by `scripts/seo-refresh.ts` and `npm run seo:load`. Pages never call DataForSEO, so browsing costs nothing. Targets (cities, keywords, AI prompts) are data in `src/data/seo/targets.ts`; competitors are discovered from the rank results, and mock competitors use `.example` domains. `src/lib/seo/match.ts` and `dataforseo.ts` are ported from OpenSEO (MIT, see `THIRD_PARTY_NOTICES.md`); billed DataForSEO calls are never retried.
- No production auth (a stub `DEV_USER` from `src/lib/session.ts`; the "No authentication" banner keys off `user.stub`) and no mutations. Controls that would write are rendered disabled; when they land, each goes behind auth and an `audit_events` insert.
- Charts are server-rendered SVG (`src/components/charts/`), no chart library, with a shared `[data-tip]` tooltip and a "View as table" disclosure on every chart. Tokens in `src/styles/global.css` (README "Visual system"): use the surface ladder, `--fs-*` sizes and `--radius*` tokens rather than raw values; no shadows or gradients on panels; colour only for status, data series, focus and the active-nav bar; IBM Plex Mono (`.label`, `.mono`, `h2`) for labels, codes and timestamps; `Panel feature` (corner brackets) on at most one hero element per page.

## Honesty rules (product requirements, not style)

- Every data panel footer names its source and the data's age.
- No composite scores: no opportunity score on Markets, no blended SEO score. Show counts with their inputs and denominators.
- Weather vs. demand is labelled correlation (Pearson r), not causation, on two charts sharing a time axis, never a dual y-axis.
- Sale prices are labelled internal-only; traffic figures are labelled as DataForSEO estimates; AI prompts stay unbranded.

Anything customer-facing must follow the ARR brand: load the `arr-bible`/`arr-brand` skills.
